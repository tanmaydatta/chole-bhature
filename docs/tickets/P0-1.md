# P0-1 · Monorepo scaffold + single Workers/D1 deploy

## Context
Phase 0 ticket (M0 · Client Demo) — the single-engineer, promo-only slice of the MVP. Spec §3 pins the real slice: a pnpm monorepo identical to the Phase 1 layout, deployed to **ONE** Workers env + **ONE** D1 via `wrangler deploy`, no dev/staging/prod matrix and no CI. Foundation ticket, no upstream dependencies. Binding decision: **evolve this repo** — do not create a new one; `apps/dashboard` carries `demo/`'s git history.

## Scope
- Root `package.json` + `pnpm-workspace.yaml` declaring `apps/*` and `packages/*` as workspace packages.
- Move `demo/` → `apps/dashboard`, preserving git history where practical.
- Scaffold buildable stubs: `apps/api` (Hono + wrangler), `apps/reference-store`, `packages/engine` (each with its own `package.json` + `tsconfig.json`).
- Shared `tsconfig.base.json` (`strict: true`, `verbatimModuleSyntax: true`) extended by every package.
- Root scripts fanning out to workspaces: `pnpm -r build`, `pnpm -r test`, `pnpm -r lint`.
- ONE Cloudflare env: a `wrangler.toml` for `apps/api` with a D1 binding; `wrangler deploy` publishes to a real, reachable URL.

## Acceptance criteria
- [ ] `pnpm install` succeeds at repo root with workspaces `apps/*`, `packages/*`.
- [ ] `apps/dashboard` is the former `demo/` app; `pnpm --filter dashboard test` runs the existing vitest suite green.
- [ ] `apps/api`, `apps/reference-store`, `packages/engine` build with `tsc -b`.
- [ ] `wrangler deploy` publishes `apps/api` to a reachable URL with a bound D1 database.
- [ ] `pnpm -r test` at root runs every workspace's test suite; tests green.
- [ ] No new repo created — `apps/dashboard` carries `demo/`'s history.

## Technical notes
- TS strict + `verbatimModuleSyntax` everywhere — every type-only import must use `import type`.
- Package manager is pnpm — no npm/yarn lockfiles.
- ONE Workers env + ONE D1 only (Spec §3): the dev/staging/prod matrix and CI are deferred to Phase 1 (INFRA-2/INFRA-3).
- `packages/engine` only needs a buildable stub here — P0-3 populates it.

## Interfaces
**Consumes:** the current repo state (`demo/` as-is); no upstream ticket.
**Produces:** the monorepo + one deployed Workers env + a bound D1 database, consumed by all later P0 tickets (P0-2..P0-8).
Seeds Phase 1 **INFRA-1** (the monorepo scaffold, delivered here) and **INFRA-2** (Phase 1 adds the dev/staging/prod env matrix + wrangler migrations tooling on top of this single env).

## Out of scope
- Durable Objects / KV / Queues.
- Multi-env matrix (dev/staging/prod).
- CI pipeline (Phase 1 INFRA-2/INFRA-3).
