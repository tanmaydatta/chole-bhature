# P0-2 · D1 schema: programs + redemptions + seed merchant

## Context
Phase 0 ticket (M0 · Client Demo) — the single-engineer, promo-only slice. Spec §5 pins the Phase 0 data model: only `programs` (with counter/cap columns) and `redemptions` (append-only ledger, idempotent by `order_id`), plus one seeded `merchants` row. Every table carries `merchant_id` even though Phase 0 is single-tenant. Depends on P0-1's D1 binding.

## Scope
- Drizzle schema for `programs` (id, `merchant_id`, `type='promo'`, status, name, JSON config, counter columns `budget_remaining` and `usage_count`, cap column `max_uses`).
- Drizzle schema for `redemptions` — append-only ledger with a UNIQUE constraint on `(merchant_id, order_id)` for idempotency.
- One seeded `merchants` row (the single hardcoded merchant).
- drizzle-kit migration applied via `wrangler d1 migrations apply`.
- A per-request Drizzle instance factory and a documented `batch()` helper (D1 has no interactive transactions).

## Acceptance criteria
- [ ] The migration runs clean on a fresh D1 database.
- [ ] The UNIQUE `(merchant_id, order_id)` constraint on `redemptions` is enforced.
- [ ] A `batch()` helper exists and is documented for writes needing atomicity across statements.
- [ ] A vitest round-trip (insert/read) for both `programs` and `redemptions` is green.

## Technical notes
- D1 has NO interactive transactions — use `batch()`; one Drizzle instance per request (avoid module-level singletons that leak across isolates).
- `programs` holds common relational columns plus a JSON config column for the promo type; the JSON shape is validated by P0-3's zod schemas, not by D1.
- `redemptions` is an append-only ledger (inserts only); D1 is history, and in Phase 0 the conditional `UPDATE` on `programs` counters is the source of truth for live caps (Spec §6).

## Interfaces
**Consumes:** P0-1's D1 binding.
**Produces:** the Drizzle schema/types for `programs` + `redemptions` + seeded `merchants`, the per-request `db` factory, and the `batch()` helper — consumed by P0-5 (programs CRUD) and P0-6 (redemptions ledger + atomic caps).
Seeds Phase 1 **BE-1** (Phase 1 adds the remaining 7 tables — `api_keys`, `variables`, `event_defs`, `codes`, `customers`, `wallet_transactions`, `program_stats` — plus type-specific config for the other program types).

## Out of scope
- Other tables (`customers` / `codes` / `wallet_transactions` / etc.).
- DO-side atomic counters (Phase 1 scale upgrade).
