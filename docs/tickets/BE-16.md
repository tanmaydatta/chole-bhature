# BE-16 · Cron jobs

> ⚠️ Detailed from the spec — refresh from the outputs of its dependencies before starting (see "Depends on").

## Context
Spec §3 (Cron Triggers) and §7 (program lifecycle). Depends on BE-8 (counters DO reset RPC).

## Scope
- Cron Trigger handler for program lifecycle transitions: `draft → scheduled → active → ended` on `programs.status`, based on program start/end dates.
- Cron Trigger handler for budget resets: calls BE-8's reset RPC to re-arm `ProgramCountersDO` and clears the corresponding `CONFIG_KV` exhausted flag, for programs configured with recurring budgets.

## Acceptance criteria
- [ ] A program past its end date transitions to `ended` on the next cron run.
- [ ] A scheduled program transitions to `active` at its start date/time.
- [ ] A budget-reset cron calls BE-8's reset RPC and clears the corresponding `exhausted` KV flag.
- [ ] Cron failures are logged and don't silently corrupt program state (partial-run safety).
- [ ] Tests green (mocked cron-trigger invocation).

## Technical notes
- Uses BE-8's reset RPC exactly — no direct DO storage manipulation from the cron handler.
- Lifecycle status values come from `packages/engine`'s `Status` union (`draft | scheduled | active | paused | ended`) — keep transitions consistent with that enum.

## Interfaces
**Consumes:** BE-8 `ProgramCountersDO` reset RPC + exhausted-flag clear.
**Produces:** the scheduled lifecycle/reset jobs — no ticket consumes this directly, but BE-6/FE-2 program-status displays reflect its writes.

## Out of scope
- Any new DO methods beyond the existing reset RPC (BE-8 owns the DO surface).
- Manual/on-demand reset from the dashboard (not in scope for MVP).
