# BE-14 · Affiliate bulk codes + CSV

> ⚠️ Detailed from the spec — refresh from the outputs of its dependencies before starting (see "Depends on").

## Context
Spec §7 — affiliate program type: "unique-code batch generation + CSV download (we own it now)." Depends on BE-6 (program config).

## Scope
- Bulk code-generation endpoint for affiliate programs, using `packages/engine`'s `generateCodes` (prefix/length/count), persisting to BE-1's `codes` table tied to the affiliate program.
- Codes-only CSV export endpoint (server-side, reusing the `toCSV` shape from `packages/engine`).
- Per-code stats query (uses/redemptions per code), backed by BE-11's redemption attribution once BE-11 lands (contract agreed now).

## Acceptance criteria
- [ ] Bulk generation creates N unique, collision-free codes for a given affiliate program and persists them.
- [ ] CSV export returns a codes-only CSV (one code per line, matching `toCSV`'s shape) sourced from the database, not regenerated client-side.
- [ ] Per-code stats endpoint returns usage/redemption counts per code (zero until BE-11 attributes redemptions).
- [ ] Tests green covering uniqueness, CSV shape, and stats shape.

## Technical notes
- Reuses `generateCodes`/`buildCodeRows`/`toCSV` from `packages/engine` (BE-3) rather than reimplementing code generation.
- `codes` (BE-1) serves both affiliate and referral — this ticket only writes affiliate-sourced rows; BE-15's referral codes reuse the same table/shape.

## Interfaces
**Consumes:** BE-6 program CRUD (affiliate program config); BE-3 `generateCodes`/`toCSV`; BE-1 `codes` table.
**Produces:** bulk-generate/CSV-export/per-code-stats endpoints and the `codes` row shape/attribution field used by redemptions — consumed by BE-11 (per-code attribution on redemption), FE-5 (codes panel + CSV download).

## Out of scope
- Referral code assignment/priority logic (BE-15).
- Client-side CSV generation (superseded — the dashboard now downloads the server-generated file, FE-5).
