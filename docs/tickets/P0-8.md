# P0-8 · Reference storefront: offers list + checkout code entry + redeem

## Context
Phase 0 ticket (M0 · Client Demo) — the single-engineer, promo-only slice. Delivers capabilities 1 and 2's shopper surface (Spec §1): the client's user sees a list of promos and enters a code at checkout to get the discount. This is the Phase 0 end-to-end proof (Spec §10). Depends on P0-6.

## Scope
- `apps/reference-store` — a minimal cart UI.
- A "Current offers" page populated from `GET /v1/promos` (publishable token).
- Checkout code entry → `POST /v1/evaluate` (show discount + message) → `POST /v1/redemptions` **before** capturing "payment".
- Re-price on a redemption rejection (exhausted promo).

## Acceptance criteria
- [ ] The offers list renders `listed` promos from `GET /v1/promos`.
- [ ] Entering a valid code shows the discount + interpolated message.
- [ ] Checkout redeems before "payment" and shows a confirmation.
- [ ] A rejected/exhausted redemption re-prices instead of proceeding.
- [ ] The full loop works against the live API.
- [ ] Tests green.

## Technical notes
- The offers page uses the publishable token; checkout's `redemptions` call uses the secret token (Spec §4 split).
- Redeem happens **before** capturing payment so an exhausted promo (Spec §6 `rowsAffected == 0`) re-prices the cart rather than letting a discount that no longer holds through to payment.

## Interfaces
**Consumes:** P0-5's `GET /v1/promos` + P0-6's `POST /v1/evaluate` and `POST /v1/redemptions`.
**Produces:** the reference storefront — the Phase 0 end-to-end proof (offers → evaluate → redeem loop).
Seeds Phase 1 **FE-6** (Phase 1 adds wallet/events display and the full multi-type loop on top of this storefront).

## Out of scope
- Wallet / events display.
- Production-grade storefront features.
- Platform connectors.
