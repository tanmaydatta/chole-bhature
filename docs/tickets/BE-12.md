# BE-12 · POST /v1/events + Queue consumers

> ⚠️ Detailed from the spec — refresh from the outputs of its dependencies before starting (see "Depends on").

## Context
Spec §4 (events contract, idempotent by event id) and §7 (loyalty accrual, referral attribution). Depends on BE-6 (event_defs) and BE-9 (wallet).

## Scope
- `POST /v1/events`: event name (e.g. `order_completed`) + payload matching `event_defs` (BE-6); secret key; idempotent by event id — enqueues to `EVENTS_QUEUE` rather than processing inline.
- Queue consumer: loyalty accrual (credit the customer's wallet via BE-9) and referral attribution (credit the referrer's wallet on the referee's qualifying event), with retries/backoff (Spec §11 reliability).

## Acceptance criteria
- [ ] A valid event enqueues successfully and the consumer credits the correct wallet(s) exactly once.
- [ ] A repeated call with the same event id does not double-credit (checked at enqueue and again at consume time).
- [ ] The consumer retries on transient failure (e.g. wallet DO unavailable) with backoff, without double-applying on eventual success.
- [ ] Unknown event names or payloads not matching `event_defs` are rejected at the API layer, not silently dropped in the queue.
- [ ] Tests green covering enqueue idempotency and consumer accrual/attribution + retry-without-double-credit.

## Technical notes
- Queue binding `EVENTS_QUEUE` (INFRA-2); the consumer is a separate Worker handler in `apps/api`.
- Loyalty never stacks (Spec §6) — accrual logic must respect that at the credit step, not just at evaluate time.
- This ticket is the "referrer credit on qualifying event" half of Spec §7's referral behavior; the "referee reward in evaluate" half lives in BE-10, and BE-15 wires the two together with priority selection.

## Interfaces
**Consumes:** BE-6 `event_defs` validation; BE-9 `CustomerWalletDO` credit RPC; INFRA-2 `EVENTS_QUEUE` binding.
**Produces:** the `POST /v1/events` idempotent contract and the queue-consumer accrual/attribution pipeline — consumed by BE-15 (referrer-credit hook), BE-17 (rollups), BE-18 (reliability-pass target), FE-6, QA-2, DOCS-1.

## Out of scope
- Referee-side reward surfacing (BE-10) and priority selection (BE-15) — this ticket only does the referrer-credit-on-event half.
- `program_stats` aggregation (BE-17).
